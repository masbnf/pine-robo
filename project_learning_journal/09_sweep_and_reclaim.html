مفهوم Sweep و Reclaim

Sweep (شکار): قیمت لحظه‌ای از لبهٔ ورودیِ Order Block (ob.entry، نه لبهٔ Stop) عبور می‌کند — انگار نقدینگیِ آن سطح را «جارو» کرده.

Reclaim (بازپس‌گیری): در همان کندل یا در یک پنجرهٔ محدود از کندل‌های بعدی (sweep_reclaim_max_bars)، قیمت دوباره به داخل ناحیهٔ OB برمی‌گردد و آنجا بسته می‌شود.

فقط وقتی هر دو اتفاق بیفتند، سفارش «تأیید» می‌شود و اجازهٔ پر شدن پیدا می‌کند. منطق این حالت: یک نفوذ کوتاه و بازگشت سریع، نشانهٔ قوی‌تری از یک ورودی واقعی معامله‌گران بزرگ است تا یک لمس ساده و بی‌بازگشت.

نکته Sweep همیشه نسبت به لبهٔ ورود OB سنجیده می‌شود، هرگز نسبت به لبهٔ Stop — کامنت صریح در کد دلیلش را توضیح می‌دهد: عبور از لبهٔ Stop دقیقاً همان شرط ابطال OB در موتور ساختار است (فصل ۸)؛ اگر Sweep روی Stop تعریف می‌شد، خودِ OB قبل از رسیدن به مرحلهٔ Reclaim باطل شده بود.

کد: _sweep_reclaim_window (خلاصه‌شده)

pine_ob_bot/paper.py — PaperBroker._sweep_reclaim_window
def _sweep_reclaim_window(self, order, candle, bar_index):
    entry = order.entry
    swept_now = (candle.low < entry) if order.direction == "bull" else (candle.high > entry)
    reclaimed_now = (candle.close >= entry) if order.direction == "bull" else (candle.close <= entry)

    if self.cfg.sweep_reclaim_max_bars == 1:
        return (swept_now and reclaimed_now), 0        # قانون اصلی: همان کندل

    # حالت آزمایشی: پنجرهٔ چندکندلی
    state = self._sr_windows.get(order.id)
    if swept_now and (state is None or deeper_sweep(candle, state)):
        self._sr_windows[order.id] = new_window(bar_index)
        state = self._sr_windows[order.id]
    if state and reclaimed_now:
        lag = bar_index - state.start_bar
        return True, lag
    if state and window_expired(state, bar_index, self.cfg.sweep_reclaim_max_bars):
        del self._sr_windows[order.id]
        self.stats["sweep_reclaim_window_expired"] += 1
    return False, 0

خط به خط: با sweep_reclaim_max_bars == 1 (مقدار پیش‌فرض)، رفتار دقیقاً «قانون همان‌کندل» اصلی است — Sweep و Reclaim باید در یک کندل واحد اتفاق بیفتند. برای مقدار بزرگ‌تر (ویژگی آزمایشی)، یک پنجرهٔ چندکندلی باز می‌شود: اولین Sweep پنجره را باز می‌کند، هر کندلی داخل پنجره که به داخل OB برگردد آن را تأیید می‌کند، و یک Sweep عمیق‌تر پنجره را ریست می‌کند.

قابلیت آزمایشی sweep_reclaim_max_bars > 1 فقط پشت پرچم صریح --sweep-reclaim-max-bars فعال می‌شود. طبق docs/ENTRY_FUNNEL_FINDINGS.md (سند کمکی پروژه)، برای XAUUSD/M5 این حالت در اولین مقایسهٔ تاریخی بی‌اثر ثبت شده — یعنی نتیجهٔ عملی قابل توجهی نسبت به قانون همان‌کندل نداشته است.

دو مسیر تأیید: کندلی در برابر تیکی

تشخیص Sweep/Reclaim از خودِ پر شدن سفارش جدا نگه داشته شده:

  • زنده: process_signal_candle روی هر کندل بسته، تأیید را بررسی می‌کند؛ در صورت تأیید فقط meta["sweep_reclaim_confirmed"] = True ست می‌شود و بافر ATR به Stop اضافه می‌شود — پر شدن واقعی همچنان به تیک بعدی موکول است (process_tick).
  • بازپخش کندلی (بک‌تست): _try_sweep_reclaim در همان کندل هم تأیید و هم پر شدن را انجام می‌دهد؛ قیمت پر شدن = close + spread برای خرید، close برای فروش (چون داده OHLC بر پایهٔ Bid است).

مفاهیم برنامه‌نویسی این فصل

پنجرهٔ وضعیت با انقضا (Windowed State with Expiry): نگه‌داشتن یک دیکشنری از «پنجره‌های باز» به‌ازای هر سفارش، با شرط انقضا، الگویی رایج در سیستم‌های رویدادمحور است — شبیه یک session با timeout.

پرچم آزمایشی پشت CLI: نگه‌داشتن رفتار پیش‌فرض ساده (max_bars=1) و قرار دادن رفتار پیچیده‌تر پشت یک پرچم صریح، یک الگوی خوب برای معرفی تدریجی قابلیت‌های جدید بدون ریسک کردن رفتار پیش‌فرض تولیدی است.

اشتباهات رایج

  • سنجیدن Sweep نسبت به لبهٔ Stop به‌جای لبهٔ Entry.
  • انتظار پر شدن فوری سفارش بلافاصله بعد از تأیید Sweep/Reclaim در مسیر زنده — تأیید و پر شدن دو رویداد جدا هستند (کندل بسته در برابر تیک بعدی).
  • فعال‌کردن sweep_reclaim_max_bars > 1 بدون آگاهی از برچسب «آزمایشی» و یافتهٔ «بی‌اثر بودن» آن روی این نماد/تایم‌فریم.

تمرین عملی

تمرین (متوسط)

در آزمایشگاه بالا، یک کندل Sweep بسازید که خیلی عمیق داخل OB نفوذ کند اما close آن هنوز بیرون از ناحیه بماند. سپس یک کندل بعدی اضافه کنید که close آن به داخل ناحیه برگردد. با sweep_reclaim_max_bars=1 در برابر sweep_reclaim_max_bars=2 نتیجه را مقایسه کنید.

راهنما

با max_bars=1، تأیید فقط اگر Sweep و Reclaim در همان کندل باشند رخ می‌دهد.

پرسش‌های مرور فصل

  1. چرا Sweep نسبت به لبهٔ Entry سنجیده می‌شود، نه لبهٔ Stop؟
  2. در مسیر زنده، تأیید Sweep/Reclaim و پر شدن واقعی سفارش چرا دو مرحلهٔ جدا هستند؟
  3. قیمت پر شدن در بازپخش کندلی برای یک سفارش خرید چگونه محاسبه می‌شود و چرا؟

خلاصهٔ فصل

Sweep and Reclaim یک لایهٔ تأیید اضافه پیش از پر شدن سفارش است: قیمت باید ابتدا از لبهٔ ورودی OB عبور کند (Sweep) و سپس در همان کندل (یا در حالت آزمایشی، در یک پنجرهٔ محدود) به داخل ناحیه بازگردد (Reclaim). با sweep_reclaim_max_bars=1 این دقیقاً قانون همان‌کندل اصلی است.
