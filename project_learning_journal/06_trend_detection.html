مفهوم: Swing تأخیری (Delayed Pivot) چیست

یک Swing High یعنی «کندلی که سقفش از سقف همهٔ کندل‌های اطرافش بالاتر است». مشکل: تا وقتی چند کندل بعدش را نبینید، نمی‌توانید مطمئن باشید سقفش واقعاً از همهٔ اطرافش بالاتر بوده — پس این تشخیص همیشه با تأخیر است. PineSwingOBEngine این تأخیر را دقیقاً cfg.trend_swing_length کندل تعریف می‌کند (پیش‌فرض ۱۲؛ یعنی حدود ۶۰ دقیقه روی M5).

کد: _update_swing

pine_ob_bot/pine_engine.py — PineSwingOBEngine._update_swing (خلاصه‌شده)
def _update_swing(self, i: int) -> None:
    n = self.cfg.trend_swing_length
    if i < n:
        return
    candidate = i - n
    window = slice(candidate + 1, i + 1)  # n کندل بعد از candidate

    is_high = all(self.parsed_highs[candidate] > h for h in self.parsed_highs[window])
    is_low  = all(self.parsed_lows[candidate]  < l for l in self.parsed_lows[window])

    new_leg = 0 if is_high else (1 if is_low else self.leg)
    if new_leg != self.leg:
        self.leg = new_leg
        pivot = Pivot(level=..., bar_index=candidate, time=..., crossed=False)
        if new_leg == 1:
            self.swing_low = pivot
        else:
            self.swing_high = pivot

خط به خط: candidate = i - n یعنی کندلی که الان بررسی می‌شود، همیشه n کندل عقب‌تر از کندل جاری i است — دقیقاً همان تأخیر. حلقهٔ all(...) بررسی می‌کند آیا candidate از هر n کندلِ بعد از خودش (تا و شامل کندل جاری) بالاتر/پایین‌تر است یا نه. اگر leg واقعاً عوض شده باشد (از سقف به کف یا برعکس)، یک Pivot جدید ساخته و ذخیره می‌شود.

نکته قبل از محاسبه، اگر کندل جاری «پرنوسان» باشد (high-low >= 2×ATR)، مقادیر parsed high/low آن جابه‌جا می‌شوند (فیلتر نویز؛ مشابه رفتار نسخهٔ اصلی Pine) — یعنی یک کندل غیرعادی بزرگ نمی‌تواند به‌تنهایی یک Pivot کاذب بسازد.

تشخیص شکست (BOS/CHoCH) و Trend State

شکست فقط بر اساس close کندل تشخیص داده می‌شود، نه high/low (کمتر حساس به فتیله): اگر یک swing_high فعال و هنوز عبورنکرده وجود داشته باشد و close کندل جاری از سطح آن بالاتر برود، یک شکست صعودی رخ داده. نوعش («BOS» یا «CHoCH») فقط به این بستگی دارد که Trend فعلی قبل از این شکست چه بوده:

  • اگر Trend فعلی همان جهت بود (یا هنوز خنثی/۰ بود) → BOS (ادامهٔ ساختار).
  • اگر Trend فعلی جهت مخالف بود → CHoCH (تغییر کاراکتر).

پس از تشخیص، self.trend بلافاصله به‌روز می‌شود (۱ برای صعودی، ۱- برای نزولی) — این یعنی همان کندلی که CHoCH رویش رخ می‌دهد، Trend را هم تغییر می‌دهد؛ شکست بعدی در همان جهت، از این به بعد BOS محسوب می‌شود، نه CHoCH.

رفتار نیازمند بررسی نظری در کد صریحاً اشاره می‌کند که در تئوری یک کندل واحد می‌تواند هم‌زمان از یک swing high و هم یک swing low عبور کند (اگر رنج آن کندل به‌شدت بزرگ باشد) — ترتیب بررسی در کد ابتدا صعودی سپس نزولی است، اما این حالت مضاعف در تست‌های موجود پروژه پوشش داده نشده.

دروازهٔ خالص: trend_filter.py

pine_engine.py فقط عدد خام Trend (۱/۱-/۰) را تولید می‌کند؛ تصمیم «آیا این جهت معامله الان مجاز است» در یک ماژول کاملاً جدا و بدون هیچ وابستگی دیگری زندگی می‌کند — trend_filter.py. این جداسازی عمدی است: همان چند تابع خالص، هم در ساخت سفارش (PaperBroker.add_ob)، هم در لحظهٔ پر شدن سفارش (PaperBroker._open) و هم در لغو سفارش هنگام تغییر Trend (update_m5_trend) صدا زده می‌شود — یعنی این دروازه حداقل سه بار، در سه لحظهٔ متفاوت، برای هر معامله بررسی می‌شود («دفاع در عمق»).

بخش واقعی پروژه: pine_ob_bot/pine_engine.py → کلاس PineSwingOBEngine، متدهای process و _update_swing. این آزمایش یک مجموعهٔ کوچک کندل از پیش تعریف‌شده را واقعاً از داخل PineSwingOBEngine عبور می‌دهد — نسخهٔ ساده‌شده نیست.

مفاهیم برنامه‌نویسی این فصل

State machine ضمنی با یک متغیر عدد صحیح: self.leg و self.trend هر دو state machine های بسیار ساده‌ای هستند که با یک عدد صحیح (۰/۱ یا ۱/۰/۱-) نمایش داده می‌شوند، نه یک enum یا کلاس جدا — الگویی رایج برای state machine های کوچک و پرتکرار در کد عملکرد-محور.

پنجرهٔ لغزان با اسلایسینگ پایتون: self.parsed_highs[candidate+1 : i+1] نمونهٔ خوبی از slicing برای گرفتن یک بازهٔ متحرک از یک لیست در حال رشد است.

اشتباهات رایج

  • فکر کردن به Swing/Trend این ماژول به‌عنوان همان Pivot فصل بعد (Entry Pivot) — این دو detector کاملاً مستقل‌اند، با پنجره‌های متفاوت و بدون اثر متقابل.
  • انتظار داشتن واکنش آنیِ Trend به یک سقف/کف تازه — واکنش همیشه trend_swing_length کندل عقب‌تر «دیده» می‌شود، نه روی خودِ کندل اکسترمم.
  • فراموش کردن اینکه شکست فقط بر پایهٔ close تشخیص داده می‌شود، نه high/low.

خلاصهٔ فصل

PineSwingOBEngine با یک پنجرهٔ تأخیری، Swing Highs/Lows را تشخیص می‌دهد؛ عبور close از یک Swing، بسته به Trend قبلی، BOS یا CHoCH نامیده می‌شود و بلافاصله Trend State را به‌روز می‌کند. این عدد خام سپس توسط دروازهٔ خالص trend_filter.py در سه لحظهٔ متفاوت طول عمر یک سفارش بررسی می‌شود.
