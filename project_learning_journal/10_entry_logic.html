نمودار قیف

هر مرحله می‌تواند مسیر را همان‌جا قطع کند؛ فقط عبور از تمام مراحل به یک PendingOrder واقعی می‌رسد.

کد کامل (خلاصه‌شده) و توضیح

pine_ob_bot/paper.py — PaperBroker.add_ob (اسکلت خلاصه‌شده)
def add_ob(self, ob: OrderBlock, extra_meta=None) -> PendingOrder | None:
    self.stats["setups_seen"] += 1

    if ob.break_kind != "unknown" and ob.break_kind not in self.cfg.allowed_break_kinds:
        return self._reject(ob, "rejected_break_kind")

    if self.cfg.strong_choch_only and ob.break_kind == "CHoCH":
        if not (extra_meta or {}).get("bos_displacement_top_quartile"):
            return self._reject(ob, "rejected_weak_choch")

    if ob.high <= ob.low or self._has_order_for(ob.id):
        return None

    trend_check = validate_trade_direction(ob.direction, self.current_m5_trend)
    if not trend_check.is_allowed:
        return self._reject(ob, trend_check.rejection_reason)

    if self.entry_pivot_gate_active:
        pivot_ok, reason = self._check_entry_pivot(ob)
        if not pivot_ok:
            return self._reject(ob, reason)

    risk = ob.high - ob.low
    target = ob.entry + self.cfg.rr * risk if ob.direction == "bull" else ob.entry - self.cfg.rr * risk
    order = PendingOrder(
        id=new_id(), ob_id=ob.id, direction=ob.direction,
        entry=ob.entry, stop=ob.stop, target=target,
        created_index=ob.formed_index, created_time=ob.formed_time,
        lifecycle_state="formed" if self.cfg.entry_lifecycle_enabled else "armed",
        meta={**(extra_meta or {}), "break_kind": ob.break_kind, ...},
    )
    self.pending.append(order)
    self.pending.sort(key=lambda o: (o.created_index, o.created_time))
    return order

خط به خط (نکات مهم): تابع در همان لحظهٔ اولین شکست، فوراً return می‌کند — هیچ ادامه‌ای بعد از رد وجود ندارد (خروج زودهنگام/Guard Clause، یک الگوی خوانایی مهم برای توابع با چند شرط پشت‌سرهم). محاسبهٔ target از یک عبارت شرطی درون‌خطی (ternary) استفاده می‌کند که جهت را در نظر می‌گیرد — برای خرید هدف بالاتر از entry، برای فروش پایین‌تر. self.pending.sort(...) بعد از هر افزودن دوباره مرتب می‌شود تا ترتیب FIFO (قدیمی‌ترین اول) برای پر شدن حفظ شود.

مثال گام‌به‌گام

فرض کنید: Trend فعلی = صعودی، یک OB صعودی با break_kind="BOS" تازه فرم شده، و دروازهٔ Entry Pivot فعال است.

  1. مرحلهٔ نوع شکست: "BOS" در allowed_break_kinds=("BOS",) هست → عبور.
  2. مرحلهٔ strong CHoCH: چون break_kind != "CHoCH"، این شرط اصلاً بررسی نمی‌شود → عبور.
  3. سلامت هندسی: high > low → عبور.
  4. دروازهٔ Trend: side="bull"، current=BULLISH → مجاز → عبور.
  5. دروازهٔ Entry Pivot: اگر آخرین Pivot Low تأییدشده، سن مناسبی دارد (کمتر از max_entry_pivot_age_bars) → عبور.
  6. یک PendingOrder با lifecycle_state="armed" ساخته و به لیست معلق اضافه می‌شود.

اگر در مرحلهٔ ۵ آخرین Pivot Low اصلاً وجود نداشت، همان‌جا با rejected_no_entry_pivot متوقف می‌شد و هیچ سفارشی ساخته نمی‌شد — حتی اگر مراحل ۱ تا ۴ کاملاً عبور کرده باشند.

مفاهیم برنامه‌نویسی این فصل

Guard Clause (خروج زودهنگام): به‌جای تودرتو کردن چند if در هم (if a: if b: if c: ...)، هر شرط رد جداگانه و در همان سطر return می‌کند — کد خطی و قابل‌ردیابی می‌ماند، حتی با هفت شرط پشت‌سرهم.

ساخت شیء غنی از متادیتا: meta روی PendingOrder یک دیکشنری باز است که هر مرحلهٔ قبلی (Entry Pivot، Displacement، M15، نقدینگی) رد پای خودش را در آن می‌گذارد — یک الگوی «context bag» رایج برای رهگیری/دیباگ سیستم‌های چندمرحله‌ای.

اشتباهات رایج

  • فکر کردن که ترتیب هفت مرحله بی‌اهمیت است — نیست: مثلاً بررسی سلامت هندسی قبل از دروازهٔ Trend می‌آید، پس یک OB نامعتبر حتی شمارندهٔ رد Trend را هم افزایش نمی‌دهد.
  • انتظار داشتن ساخت سفارش برای هر OB تازه — بسیاری از OBها همان لحظهٔ ساخت رد می‌شوند و هرگز PendingOrder نمی‌شوند.

تمرین عملی

تمرین (پیشرفته) — طبق فهرست تمرین‌های اصلی: «اضافه‌کردن یک فیلتر ورود»

فرض کنید می‌خواهید یک فیلتر جدید اضافه کنید: رد هر OB که atr_at_formation آن کمتر از یک آستانهٔ مشخص باشد (نویز خیلی کم). این بررسی باید در کدام نقطهٔ قیف بالا قرار بگیرد و چرا؟ چه شمارندهٔ آماری جدیدی باید اضافه شود؟

راهنما

به الگوی هر مرحلهٔ موجود نگاه کنید: یک شرط + یک return self._reject(ob, "...") + یک شمارندهٔ متناظر در stats.

پرسش‌های مرور فصل

  1. هفت مرحلهٔ قیف پذیرش را به ترتیب نام ببرید.
  2. چرا بررسی سلامت هندسی OB هیچ شمارندهٔ آماری ندارد اما بقیهٔ ردها دارند؟
  3. اگر Entry Pivot گیت غیرفعال باشد، مرحلهٔ ۵ چه می‌شود؟

خلاصهٔ فصل

PaperBroker.add_ob نقطه‌ای است که فصل‌های ۶ تا ۹ به هم می‌رسند: نوع شکست، قدرت CHoCH، جهت Trend و تازگی Entry Pivot، همه به‌ترتیب و با الگوی Guard Clause بررسی می‌شوند. فقط عبور از هر هفت مرحله یک PendingOrder واقعی می‌سازد.
